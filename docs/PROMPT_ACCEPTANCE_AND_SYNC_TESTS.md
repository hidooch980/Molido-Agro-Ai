## پروتکل پیشنهادی برای تکمیل

1. هر تغییر محلی باید در همان تراکنش Room، موجودیت و رکورد outbox را ثبت کند.
2. هر عملیات دارای idempotency key پایدار باشد؛ تکرار درخواست نباید اثر دوم ایجاد کند.
3. Worker فقط عملیات موعدرسیده را batch کند و تا دریافت تأیید معتبر، عملیات را SYNCED نکند.
4. سرور باید idempotency key را یکتا نگه دارد و نسخه رکورد را برگرداند.
5. تعارض به CONFLICT برود؛ هیچ last-write-wins پنهانی مجاز نیست.
6. خطاهای شبکه/5xx قابل retry و خطاهای اعتبارسنجی/مجوزی دائمی تلقی شوند.
7. payload حساس در صف محلی محافظت شود؛ کلید یا token در مخزن و APK قرار نگیرد.
8. حذف یا تغییر داده باید tombstone/version داشته باشد تا در همگام‌سازی دوطرفه حذف از بین نرود.

## معیار قبولی

تا زمانی که همه آزمون‌های جدول «مواردی که هنوز عملیاتی نیستند» روی پیاده‌سازی واقعی و مقصد واقعی اجرا نشده‌اند، قابلیت همگام‌سازی نباید «فعال» یا «کامل» نمایش داده شود.
